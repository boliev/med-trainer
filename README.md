# Практика — медицинские учебные тренажёры

Минималистичный сайт на React + TypeScript + Vite для самостоятельного повторения алгоритмов. Мобильная версия есть.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173`).

Сборка для публикации:

```bash
npm run build
npm run preview
```

Готовый статический сайт появляется в `dist/`. Хостинг должен направлять неизвестные URL на `index.html` (SPA fallback), чтобы ссылки `/check` и `/check/1` открывались напрямую. В конфигурации Nginx внутри `location /` обычно достаточно `try_files $uri $uri/ /index.html;`.

## Страницы

- `/` — главная, с отдельной карточкой тренажёра и местом под будущие разделы.
- `/check` — список алгоритмов, поиск, избранные сверху с разделителем.
- `/check/:id` — обучение (последовательное раскрытие и оценка), повторение ошибок, экзамен.

Избранное и результаты самостоятельной оценки сохраняются в `localStorage` **только текущего браузера и устройства**. Если почистить данные браузера, прогресс исчезнет. Синхронизации между телефонами и компьютерами пока нет.

## Как добавить чек-лист

1. Положите новый файл `*.json` в **`checklists/`** (это отдельная папка в корне проекта, не компонент React).
2. Используйте новый уникальный числовой `id` (например, 5).
3. Укажите `name`, `parts` (группы), внутри каждой группы `pos`, `name`, `items` с `pos`, `item` и необязательным `hint`.
4. В режиме разработки файл автоматически увидит Vite. Для публикации повторите `npm run build` и загрузите новый `dist/`.

Пример:

```json
{
  "id": 5,
  "name": "Название нового алгоритма",
  "parts": [
    {
      "pos": 1,
      "name": "Подготовка к процедуре",
      "items": [
        {"pos": 1, "item": "Первое действие", "hint": "Необязательная подсказка"},
        {"pos": 2, "item": "Второе действие", "hint": ""}
      ]
    }
  ]
}
```

**Важно:** все номера `items[].pos` внутри одного чек-листа должны быть уникальными и обозначать сквозной порядок (1, 2, 3, …). `id` не менять после публикации, иначе ранее сохранённые избранное и оценки могут перестать соответствовать материалу. Данные остаются в оригинальной формулировке, приложение **не проверяет медицинскую корректность** исходных алгоритмов.

## Оценки

- **Вспомнила:** вспомнила действие и важные детали.
- **Частично:** действие назвала, но упустила существенную деталь.
- **Забыла:** не смогла воспроизвести действие.

«Ошибки» показывает пункты, которые в **последней сохранённой оценке** обозначены как «Частично» или «Забыла». После удачного повторения они уйдут из списка ошибок.

«Экзамен» показывает полный алгоритм только после устного воспроизведения; после раскрытия можно отметить пропущенные пункты и сохранить результат. Это самопроверка, не оценка преподавателя.

## Особенности импортированных файлов

Исходные четыре JSON содержали синтаксические ошибки (лишние конечные запятые, недостающая закрывающая скобка в файле 4) и повторяющийся `id=1` в файлах 1 и 3. Исправлены **только технические моменты**; id третьего файла изменён на 3. Тексты пунктов оставлены как в переданных файлах. В случае пустого названия части приложение показывает «Этап 1» (оригинальное поле JSON при этом не меняется).
